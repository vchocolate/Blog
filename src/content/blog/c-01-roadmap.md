这是「C 语言学习笔记」系列的第一篇。与其一上来就写语法，不如先把路线说清楚：这门课学什么、为什么这样学、会遇到什么困难。后面的笔记都会按这个路线推进。

## 为什么大一要学 C 语言

客观地说，C 语言在今天不是写业务软件的首选，但它仍然是大一计算机相关专业的必修课，原因主要有三个：

- **贴近底层**：指针、内存、数组与地址的关系，是理解计算机工作原理的入口。后面学数据结构、操作系统、编译原理，都要用到这些概念。
- **语法核心小**：C 的关键字只有几十个，语法规则不多，难的是「用这些简单的规则组合出正确的程序」。
- **训练价值**：没有垃圾回收、没有丰富的标准库兜底，写 C 会逼你弄清楚每一块内存从哪来、到哪去。

## 客观预期：会难在哪里

先打预防针，避免中途受挫：

| 阶段 | 常见困难 | 应对方式 |
| --- | --- | --- |
| 基础语法 | 细节多，容易忘 | 每个知识点都自己敲一遍，编译一遍 |
| 数组与字符串 | 下标越界、`'\0'` 搞不清 | 画内存图，手工模拟 |
| 函数与递归 | 值传递理解不透 | 用调试器单步观察变量 |
| **指针** | 全课程最大难关 | 画图 + 多写，不要只看不练 |
| 文件与内存管理 | 错误处理容易忽略 | 养成检查返回值的习惯 |

指针是公认的难点，不是智商问题，是练习量问题。笔记（十一）（十二）会花很大篇幅讲，那时候再看。

## 工具选择

- **编译器**：Windows 上用 MinGW-w64（GCC），macOS 自带 clang，Linux 装 `gcc` 即可。命令行编译看着朴素，但报错信息最清楚。
- **编辑器**：VS Code 加 C/C++ 插件是主流选择；学校机房常用的 Dev-C++ 也能用，寿命长、配置简单；如果课程用 Visual Studio，跟着课程走即可。
- **调试器**：GDB。第 17 篇会讲最常用的几条命令。

> 工具只是工具。真正要练的是「写代码 → 编译报错 → 根据报错定位 → 修改」这个循环。

## 资料参考

- 教材：谭浩强《C 程序设计》是国内课程最常用的教材，例子偏旧、个别写法不够规范，但跟课够用；想深入可以配《C Primer Plus》或者 K&R 的《The C Programming Language》。
- 在线：cppreference 查标准库函数最准确；菜鸟教程适合速查语法。
- 视频课：浙大翁恺老师的 C 语言课口碑比较好，适合课前预习。

资料不要贪多，选定一套主线 + 一份速查即可。

## 学习方法（我给自己定的规矩）

1. **代码必须自己敲**：看十遍不如敲一遍，尤其是报错信息，要自己读。
2. **每个例子都编译运行**：笔记里的代码我都实际编译过，你也可以改几个数字再跑一次。
3. **画内存图**：数组、指针、字符串，画图比背规则有效。
4. **当天消化**：每天 1 小时，好过周末突击 8 小时。
5. **记录错误**：把遇到的编译错误和解决方法记下来，第 17 篇就是干这个的。
