工欲善其事，必先利其器。这一篇把环境搭好，并跑通第一个程序。

## 源代码到程序：编译的四个阶段

C 代码要经过四个阶段才能变成可执行文件：

1. **预处理**：处理 `#include`、`#define`，展开头文件、替换宏。
2. **编译**：把 C 代码翻译成汇编代码。
3. **汇编**：把汇编代码翻译成机器码（目标文件 `.o` / `.obj`）。
4. **链接**：把目标文件和库函数拼在一起，生成可执行文件。

平时一条 `gcc` 命令就完成了全部工作，但理解这四个阶段，遇到「未定义引用」这类报错时就知道该往哪查。

## Windows：安装 MinGW-w64（GCC）

1. 下载 MinGW-w64（推荐 MSYS2 或 WinLibs 的整合包）。
2. 安装后把 `bin` 目录加入系统环境变量 `Path`，例如 `C:\mingw64\bin`。
3. 打开新的命令行窗口验证：

```bash
gcc --version
```

能打印版本号就说明装好了。如果提示「不是内部或外部命令」，说明 `Path` 没配好，重新检查路径并**重开**命令行。

## VS Code 配置要点

- 安装扩展：**C/C++**（Microsoft）。
- 装好编译器后，VS Code 一般能自动识别；不能识别时在设置里指定 `C_Cpp.default.compilerPath`。
- 终端里直接用 `gcc` 编译即可，不必急着折腾复杂的 `tasks.json`。

如果课程要求用 Dev-C++ 或 Visual Studio，也完全可以，重点是理解代码本身。

## 第一个程序

新建文件 `hello.c`：

```c
#include <stdio.h>

int main(void) {
    printf("Hello, World!\n");
    return 0;
}
```

编译并运行：

```bash
gcc hello.c -o hello
./hello        # Windows 下为 hello.exe，直接输入 hello 回车
```

输出：

```text
Hello, World!
```

## 程序结构逐行拆解

```c
#include <stdio.h>   /* 1. 预处理指令：引入标准输入输出库的声明 */
int main(void) {     /* 2. 主函数：程序唯一的入口 */
    printf("...");   /* 3. 语句：以分号结尾 */
    return 0;        /* 4. 返回 0 表示程序正常结束 */
}                    /* 5. 函数体结束 */
```

几个要点：

- **每个 C 程序有且只有一个 `main` 函数**，程序从它开始执行。
- 语句结尾必须有分号 `;`，漏写是最常见的错误。
- `#include` 是预处理指令，**行尾不加分号**。
- `\n` 是换行符，见下一篇的转义字符。

## 常见报错与解决

| 报错信息 | 原因 | 解决 |
| --- | --- | --- |
| `'gcc' 不是内部或外部命令` | 环境变量没配 / 没重开终端 | 检查 Path，重开命令行 |
| `error: expected ';' before ...` | 上一行漏分号 | 看报错上一行 |
| `undefined reference to 'main'` | 没有 main 函数或拼错 | 检查拼写，注意大小写 |
| 中文输出乱码 | 终端编码不是 UTF-8 | `chcp 65001` 或用 Windows Terminal |
| `Permission denied` | 输出文件正在运行/被占用 | 关掉正在运行的程序再编译 |

读报错的方法：**从第一条错误看起**，后面的错误常常是第一条引起的连锁反应。

## 练习

1. 把 `Hello, World!` 改成你的名字，重新编译运行。
2. 故意删掉一个分号，观察报错信息，再改回来。
3. 故意把 `main` 拼成 `mian`，看看链接阶段报什么错。
